# Dependency and licence policy

## Allowed by default

A dependency may be accepted where its complete use is compatible with GNU AGPL version 3 and distribution obligations can be met. Common permissive licences may be accepted after verification, including MIT, BSD-2-Clause, BSD-3-Clause, ISC, Apache-2.0 and Zlib.

GNU GPL version 3 and GNU AGPL version 3 components require a specific combination and source-distribution review. GNU LGPL components require dynamic/static-link and relinking analysis. MPL-2.0 components require file-level source availability and notice preservation.

## Manual review required

Manual legal review is required for:

- any custom, non-SPDX or source-available licence;
- Commons Clause, SSPL, BSL, Elastic Licence, PolyForm or similar terms;
- AGPL/GPL/LGPL dependencies;
- OpenSSL or advertising-clause variants;
- fonts, icons, maps, models, test corpora or databases;
- code generated by a service with unclear output rights;
- copied Stack Overflow or forum code;
- a Git dependency, fork or unpublished crate;
- vendored code;
- a package whose repository and packaged licence differ;
- dual licensing where the selected option is unclear;
- “no commercial use”, “ethical use”, field-of-use or platform restrictions;
- abandoned or unmaintained security-critical dependencies.

## Prohibited

Do not merge or release:

- code with no identified licence;
- material copied from an employer or confidential source;
- code subject to an incompatible proprietary restriction;
- leaked source, credentials or personal data;
- a dependency whose required source or notices cannot be distributed;
- a dependency that would require relicensing material Magrathean cannot relicense.

## Automated controls

CI should run, at minimum:

- `cargo metadata --locked --all-features`;
- `cargo deny check advisories bans licenses sources`;
- `cargo about generate`;
- `cargo sbom` or an equivalent CycloneDX/SPDX generator;
- REUSE linting;
- secret scanning;
- source/header classification checks.

Generated output must be retained with each release.

## Lockfile changes

Every `Cargo.lock` change requires dependency diff review. A reviewer must record new packages, removed packages, licences, source changes, build scripts, native code and security impact.
