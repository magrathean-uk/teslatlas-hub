# GNU AGPL compliance

## Source distributions

Include the licence, applicable notices, source, build/install scripts, interface definitions, generated-source inputs, dependency metadata and modification dates.

## Object code

Provide equivalent no-charge access to complete Corresponding Source for the exact binary. A moving `main` branch is not enough.

## Network interaction

A modified version used by remote users must prominently offer those users Corresponding Source for the version actually running.

Recommended endpoints/interface items:

- `/legal`
- `/source`
- discovery document with version, commit and immutable source URL
- CLI `legal` and `source`
- GUI About / Legal / Source

## Appropriate legal notices

Interactive interfaces should identify copyright, no warranty, AGPL rights, licence location, source route and required attribution.

## Separate programs

Ordinary protocol communication does not automatically combine two programs. Shared code, intimate internal structures, linking, one inseparable installer or a deliberately combined work may change the analysis.

## Forbidden extra restrictions

Do not add non-commercial terms, competitor bans, royalties, mandatory promotion, use reporting, field restrictions or interoperability bans.

## Enforcement

Before alleging breach, preserve the exact release, identify the rightsholder and covered material, map facts to licence clauses, respect cure provisions and obtain legal review before a platform notice or litigation.
