# Full parity rehearsal v1

The rehearsal is a clean, disposable, native-host journey using a signed release
artifact, the representative corpus, the pinned TeslaMate reference runner,
and fresh Hub state/credentials. It never uses the user's TeslaMate deployment
or production database. It begins with no Hub service, state, TLS identity,
pairing, credential, pack, or report, and it forbids manual database edits,
repair shortcuts, unrecorded retries, and source mutation by Hub.

1. Verify release manifest/signature and artifact provenance; install Hub and
   prove clean state/permissions, native supervision, readiness, and pairing.
2. Run read-only discovery/preflight, then direct typed capture of the selected
   corpus vehicle. Prove bounded parallel copy/stage, reconciliation, pack and
   manifest verification, zero unexplained differences, timing/resource profile,
   and Teslatlas full-sync atomic activation.
3. Exercise optional candidate credential handoff without enabling dual refresh;
   prove redaction, non-secret identity/scope, rollback custody, and unchanged
   source credentials.
4. Run the one-minute no-wake probe against the simulator and separately record
   the required real owner-authorized physical-wake proof on an eligible native
   host. The real proof is a bounded read only; it does not grant production
   cutover authority.
5. Complete the manually invoked read-only verification window, including
   health, immutable parity, storage/WAL, credentials, backup/restore, and
   source-drift checks. No TeslaMate timer or service action is installed.
6. Generate a signed cutover plan. In disposable infrastructure, the operator
   independently performs the plan's source-side transition, confirms it, then
   activates Hub. Prove one authority, no source writes by Hub, durable
   collection, freshness/state handling, and paired sync.
7. Inject source/network/storage/crash/corruption and pressure failures at every
   required named boundary. Prove truthful readiness, zero lost acknowledged
   facts, zero duplicate projected facts, correct quarantine, and no manual
   repair.
8. Generate and execute the signed rollback plan in the disposable environment:
   stop Hub, seal/verify the Hub-only interval export, deactivate Hub authority,
   and have the operator restore source authority. Prove retained provenance,
   source integrity, final readiness, backup restore, upgrade/refusal paths,
   and data-preserving removal.

Each step emits a redacted, signed/digested rehearsal record tied to release,
host/profile, corpus, source/reference, scenario, command, timing, resource,
request audit, and expected/actual outcome. The final ledger must identify
every skipped, failed, or manually resolved action; any manual repair,
unexplained database difference, missing native/platform proof, invalid
signature, breached hard limit, or source mutation by Hub fails the rehearsal.
Passing rehearsal is readiness evidence only. It never performs production
cutover; a later operator must independently approve and execute a fresh plan.
