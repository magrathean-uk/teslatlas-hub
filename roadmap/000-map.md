# TeslaMate Backend Parity Wayfinder Map

## Destination

An execution-ready specification for a production Rust backend that reaches
declared TeslaMate backend parity for Teslatlas, including safe migration,
credential handoff, live collection proof, delayed cutover, rollback, exhaustive
database validation, and evidence-based adaptive performance.

## Notes

- This repository uses the local-markdown tracker.
- Numbered files are a strict decision order. The frontier is the first open
  file whose named blocker is closed.
- Supported first platforms are Apple-silicon macOS, Debian amd64, and Debian
  arm64. Intel macOS is not a first-platform target.
- TeslaMate `4.1.0-dev` is the moving reference line. Each development stage
  pins one exact clean `origin/main` commit and never chases a moving head
  mid-stage.
- TeslaMate is an absolute read-only source. Planning and future migration may
  read its database, files, service metadata, and container metadata, but may
  not write its database, change configuration, mutate containers, install a
  timer, or stop, start, restart, pause, disable, or enable any TeslaMate unit.
- Migration speed is a release gate. The initial target is under 10 minutes for
  the existing roughly 10-million-row representative database on a supported
  baseline host, with a 30-minute hard ceiling. A design approaching one hour
  is rejected and redesigned.
- Each ticket records a question and a starting recommendation. A resolution is
  added only when that ticket is worked and then its status changes to closed.
- A ticket question is work for the agent, not automatically a question for the
  user. Every ticket is AFK unless its frontmatter explicitly says `mode: HITL`.
- Resolve questions in this order: pinned TeslaMate source and tests, current
  Hub and Teslatlas source, official external contracts, measured prototype or
  benchmark, then a conservative documented inference.
- Never ask the user for an arbitrary target number when reference behavior or
  measurement can supply it. If TeslaMate has no formal promise, derive a
  testable threshold from its observed cadence and failure behavior, record the
  inference, and continue.
- Ask the user only for a deliberate product deviation, business or legal
  preference, unavailable credential/access, physical action, production
  authority, or destructive/external mutation.
- Freshness baseline is locked: driving data at most 5 seconds old, charging at
  most 10 seconds, ordinary online data at most 75 seconds, and no freshness SLA
  while asleep or offline; report the last-observation age and never wake.
- Crash recovery baseline is locked: Hub returns to truthful readiness within
  60 seconds on a supported baseline host, with zero loss after durable
  acknowledgement and no duplicate projected facts.
- One future agent session works one numbered ticket only. Before code, that
  ticket is split into tracer steps when needed; each tracer step owns one
  behavior, normally touches no more than three production files and one focused
  test file, contains at most one schema change, and is independently reversible.
- If a step cannot fit comfortably inside 25,000 total working tokens, the agent
  must split it before reading broadly or editing.
- Use Wayfinder for every ticket. Use Grill-with-docs only for choices that
  cannot be resolved from source, tests, official contracts, or measured facts.
- The supported TeslaMate reference is local source until the first ticket pins
  an exact version and commit.
- GitHub is storage only. No GitHub CI, build, or test dependency is introduced.
- Planning does not authorize production credentials, production migration, or
  stopping a running TeslaMate service.

## Not yet specified

- Deviations that become visible after the TeslaMate reference inventory.
- Exact Fleet Telemetry mechanics after current official contracts are reviewed.
- Dataset-specific migration exceptions exposed by the representative corpus.
- Hardware-specific tuning dimensions exposed by baseline profiling.
- Later tickets may be split, merged, or retired when an earlier resolution
  changes the route.

## Out of scope

- Grafana dashboards, Phoenix web UI, and a replacement interactive web frontend.
- Vehicle commands, charging commands, and wake commands.
- Reusing TeslaMate application code or keeping TeslaMate as a runtime dependency.
- Production cutover before the complete migration rehearsal and rollback proof.
- Automated or scheduled mutation of a running TeslaMate service, database,
  Docker deployment, containers, or configuration.
- Teslatlas UI work beyond defining and proving its backend data contract.
